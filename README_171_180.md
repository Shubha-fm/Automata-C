# Programs 171–180: Configurable Automata and Advanced Algorithms

These ten standalone C11 programs introduce reusable string matching, table-driven automata, graph export, state minimization, and automata-theoretic language checks. Unlike many earlier examples, several programs read automata from files rather than using only a built-in machine.

| Number | C source | Functionality |
|---:|---|---|
| 171 | [KMP binary match](programs/171_kmp_binary_match.c) | Find the first occurrence of a configurable binary pattern |
| 172 | [Aho-Corasick](programs/172_aho_binary_patterns.c) | Report all matches of the built-in patterns `001`, `010`, and `111`, including overlaps |
| 173 | [DFA from file](programs/173_dfa_file_simulator.c) | Simulate a finite-state transition table for a binary word |
| 174 | [NFA from file](programs/174_nfa_file_simulator.c) | Simulate nondeterministic transitions represented as bitsets |
| 175 | [ε-NFA from file](programs/175_epsilon_nfa_file_simulator.c) | Apply epsilon closure before and after each consumed symbol |
| 176 | [DFA to DOT](programs/176_dfa_dot_export.c) | Produce a Graphviz-compatible DFA diagram |
| 177 | [DFA partition minimization](programs/177_dfa_partition_minimization.c) | Iteratively identify equivalent states in a built-in DFA |
| 178 | [Büchi nonemptiness](programs/178_buchi_nonemptiness.c) | Check whether an accepting state lies on a reachable cycle |
| 179 | [Moore minimization](programs/179_moore_partition_minimization.c) | Minimize a built-in Moore machine, preserving output behavior |
| 180 | [DFA equivalence](programs/180_dfa_equivalence_from_files.c) | Compare two DFA files and return a shortest counterexample when different |

## Compile and test

```sh
make
make test-171-180
```

## Examples

```sh
./bin/171_kmp_binary_match 001 100101
./bin/172_aho_binary_patterns 0010111
./bin/173_dfa_file_simulator examples/dfa_ends_01.txt 1101
./bin/174_nfa_file_simulator examples/nfa_contains_01.txt 1001
./bin/175_epsilon_nfa_file_simulator examples/enfa_contains_01.txt 1001
./bin/176_dfa_dot_export examples/dfa_ends_01.txt > automaton.dot
./bin/180_dfa_equivalence_from_files examples/dfa_ends_01.txt examples/dfa_ends_1.txt
```

## Input file formats

DFA files (programs 173, 176, and 180) use:

```text
number_of_states start_state number_of_final_states
final_state_1 final_state_2 ...
q0_on_0 q0_on_1
q1_on_0 q1_on_1
...
```

State IDs start at 0. A valid DFA must have 1–32 states (program 180 supports up to 16). Every transition points to a valid state. An empty list of accepting states is allowed.

NFA files (program 174) use `number_of_states start_state final_mask` followed by two unsigned decimal transition masks (`on_0 on_1`) for every state. ε-NFA files (program 175) have three masks per state (`on_0 on_1 epsilon`). A mask has bit *i* set if state *i* is included. The NFA tools support at most 16 states.

## Limits

- The KMP matcher accepts a pattern of 1–4096 bits.
- Aho-Corasick uses three fixed patterns. Its trie and failure links are constructed at runtime.
- The graph algorithms for programs 177–179 use clearly specified built-in example machines.
- Program 180 uses a breadth-first product-state search, so the counterexample is shortest in the number of input symbols.
